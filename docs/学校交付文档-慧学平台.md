# 学校交付文档 - 慧学 平台

> 文档用途: 供学校信息中心与教务管理人员接收、运维、开课使用。  
> 文档边界: 本文基于当前 慧学 仓库内已交付资源、部署脚本、验收文档与手册内容静态核对整理，不描述未闭环功能，不扩展教师使用指南。  
> 项目名约定: 对外统一使用 `慧学`，历史仓库目录仍为 `huixue-yuanban`。

## 1. 平台概述

慧学 是一套面向高校的数据分析教学与编程实训平台，用于承载 BI 数据分析教学、项目实训、课堂管理、资源管理与学生学习过程记录。

当前平台服务的两个核心场景如下:

1. BI 数据分析教学  
   学生在课堂内进入具体实训案例，基于真实或仿真业务数据完成数据理解、指标分析、可视化设计和结果提交。
2. 编程实训  
   学生按阶段完成 Python、大数据、数据清洗、数据挖掘、神经网络、计算机视觉等课程实践关卡，平台记录关卡进度与成绩。

当前真生产交付范围内可用的功能包括:

- 用户登录与角色区分: 管理员、学校管理员、教师、学生
- 课堂列表与课堂详情页
- BI 实训工作区
- 课程实践/关卡式实训
- 教学资源预览与下载
- 教师查看课堂、资源、成绩与提交记录
- 管理端课程/实训/用户基础管理

## 4. 学校上线步骤（按时间顺序）

### 4.1 第 1 周: 信息中心接管

1. 修改 `school_admin` 密码
2. 验证保留课堂、BI training 与 practice 在平台前端可见
3. 配置校园内网、机房、宿舍等访问路径
4. 明确由学校哪一侧负责平台日常启停与账号维护

### 4.2 第 2 周: 教务对齐

1. 与各专业教师确定本学期使用哪些课程与实训
2. 决定每位教师对应使用哪个 classroom 模板
3. 明确哪些课程先使用 BI 实训，哪些课程先使用编程实践

### 4.3 第 3 周: 账号体系

1. 批量创建真实教师账号（约 10 个）
2. 批量创建真实学生账号（约 70 个）
3. 学生加入对应 classroom
4. 按班级完成课程分配和课堂检查

### 4.4 第 4 周: 学期开课

1. 教师正式使用平台组织课程
2. 学生进入课堂学习与提交作业
3. 学校收集首轮访问、资源、成绩、提交等反馈

## 5. 常见运维操作

### 5.1 改密码（`school_admin` 必做）

方式一: 后台界面

1. 登录平台
2. 进入用户管理
3. 找到 `school_admin`
4. 修改密码并保存

方式二: 后端 SQL

```sql
UPDATE api_users
SET hashed_password = '<新哈希>'
WHERE id = 6;
```

密码哈希算法: `pbkdf2_sha256`  
代码位置: `backend/app/core/security.py`

### 5.2 批量建老师账号

当前建议方式:

- 直接插入 `api_users`
- 同步补齐 `user_profiles`

备注: 当前交付范围内未单独实现“批量导入教师账号”管理界面，学校信息中心接管初期建议由技术运维侧统一执行。

### 5.3 批量建学生账号

当前建议方式与教师相同:

- 直接插入 `api_users`
- 同步补齐 `user_profiles`

### 5.4 修改 classroom 教师

```sql
UPDATE classrooms
SET teacher_id = <新老师id>
WHERE id = <classroom id>;
```

### 5.5 重启服务

1. SSH 登录 Web 节点
2. 重启前端/后端

```bash
sudo docker restart huixue-frontend
sudo docker restart huixue-backend
```

3. 重启后等待约 30 秒
4. 在学校内网访问 `http://<慧学内网IP-1>:3000` 验证登录页或首页可打开

### 5.6 备份 / 恢复

数据库备份建议:

```bash
docker exec -it huixue-db-prod pg_dump -U huixue -d huixue > huixue-backup.sql
```

若学校当前运行容器名称不是 `huixue-db-prod`，请先执行 `docker ps` 以当前真实容器名为准。

文件备份建议:

- 资源文件位于 NFS 共享存储
- 数据节点统一存放教学资源与相关文件

备份频率建议:

- 常规学期: 每周 1 次
- 开学初与考试周: 每天 1 次

## 6. 已知问题（Active P3）

以下条目来自当前 `KNOWN_ISSUES.md` 的 Active 项，属于已知边界或后续优化项，不影响学校先行接管主流程。

### 6.1 Browser Use / Playwright 真鼠标点击不稳

- 性质: 开发与自动化测试工具边界
- 影响: 主要影响 Codex/Playwright 自动化点击 BI/AI Designer 某些节点
- 对真实用户影响: 正常浏览器用户通常不受此问题直接影响

### 6.2 dashboard “课程总数 15” 与“18 门课规划”数字差异

- 当前真值: dashboard 统计展示 15
- 原因: 平台当前 `courses` 真行数为 15；“18 门课”属于历史规划口径
- 学校处理建议: 保持现状即可，后续如需统一宣传口径，可补录课程行或调整文案

### 6.3 pytest sandbox 无网络/文件隔离

- 性质: 架构治理项
- 影响: 面向不可信公开提交时存在沙箱隔离不足问题
- 当前状态: 不阻塞本次学校交付范围

### 6.4 logging WARNING 输出无统一 handler

- 性质: 可观测性优化项
- 当前状态: 不影响平台主功能正确性

### 6.5 学校 DB 容器历史漂移

- 现象: 学校环境可能同时存在 stopped 的 `huixue-db` 与当前运行中的实际数据库容器
- 建议: 运维操作前先执行 `docker ps`，以当前运行容器为准，不直接依据历史文档命名
